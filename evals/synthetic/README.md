# evals/synthetic: synthetic eval sets (PROTECTED)

Small eval sets that are built only on the synthetic mailbox (`tests/fixtures/synthetic_mailbox/`,
generated by `scripts/gen_synthetic_mailbox.py`). They exercise the eval code, the smoke run and
the tests on CPU, without real mail. **Their numbers say nothing about quality on real mail**;
reportable numbers come from the private sets through `make exp` (CLAUDE.md, decisions #21).

## Rules
- Frozen per version (`<name>-vN`). Never edit a frozen set: cut `<name>-v(N+1)` in a plan.
- Protected path: created or changed only in a session the user starts with
  `CLAUDE_UNLOCK_PROTECTED=<the plan step's globs>`, then committed and relocked.
- Expected messages are referenced by `mid` (decisions #5) or by fixture key, as listed in
  `tests/fixtures/synthetic_mailbox/MANIFEST.json`. Never by Thunderbird ids.
- Synthetic content only: reserved domains (`example.com`/`.org`/`.net`, `.test`), English and
  Greek (A-22).

## Private sets of the same name
A synthetic set and the private set with the same name and version (e.g. `qa-v1`) are **different
sets**. Private sets are labelled by the user on real mail and live outside the repo, in
`~/.local/share/tern/evals/`. Claude Code sessions never read them (CLAUDE.md hard rules). Only
their aggregate metrics, with name, version and sha256, reach `runs/`.
